> Constituição destinada a regulamentar a auditoria institucional, cultural, editorial, documental, técnica, operacional e patrimonial; os controles permanentes de conformidade; o tratamento das não conformidades; a verificação da rastreabilidade; e a certificação periódica da integridade do Portal Permanente da FESTANÇA de Vila Bela da Santíssima Trindade – Mato Grosso – Brasil.

## 2. Finalidade

Esta Política estabelece o regime oficial de auditoria e conformidade do Portal Permanente da FESTANÇA.

Sua finalidade é assegurar que a arquitetura institucional, cultural, documental, editorial, técnica e operacional permaneça:

- legítima;
- íntegra;
- coerente;
- rastreável;
- segura;
- verificável;
- recuperável;
- compatível;
- historicamente preservada;
- institucionalmente responsável;
- culturalmente fiel;
- continuamente auditável.

---

## 3. Missão da auditoria

A auditoria deverá proteger simultaneamente:

- a autenticidade da FESTANÇA;
- a memória da edição fundadora;
- os registros históricos;
- os grupos tradicionais;
- as autoridades legítimas;
- os documentos constitucionais;
- os contratos de dados;
- os arquivos técnicos;
- a continuidade do Portal;
- a confiança pública;
- as futuras edições.

---

## 4. Princípio fundamental

Nenhum ativo relevante deverá ser considerado íntegro apenas porque existe.

Sua integridade deverá poder ser:

- demonstrada;
- verificada;
- comparada;
- documentada;
- reproduzida;
- recuperada;
- certificada.

---

## 5. Regra constitucional

Toda auditoria deverá observar:

1. independência proporcional;

## 7. Conceito de auditoria

Auditoria é o processo sistemático, documentado e verificável destinado a comparar o estado real de um ativo, processo ou decisão com:

- a Constituição de Governança;
- as políticas aplicáveis;
- os documentos oficiais;
- os contratos técnicos;
- as decisões registradas;
- os critérios culturais;
- os requisitos históricos;
- os controles de preservação;
- os padrões de integridade.

---

## 8. Conceito de conformidade

Conformidade é a condição na qual um ativo, processo, documento ou decisão atende aos requisitos aplicáveis de:

- autoridade;
- conteúdo;
- forma;
- origem;
- aprovação;
- implementação;
- segurança;
- versionamento;
- preservação;
- rastreabilidade;
- recuperação;
- certificação.

---

## 9. Conceito de integridade

Integridade é a condição na qual um ativo permanece:

- completo;
- autêntico;
- coerente;
- não adulterado;
- contextualizado;
- relacionável à sua origem;
- compatível com seus contratos;
- tecnicamente utilizável;
- historicamente recuperável.

## 28. Modalidades de auditoria

As auditorias poderão ser:

| Modalidade | Característica |
|---|---|
| Preventiva | Realizada antes da execução |
| Concomitante | Realizada durante a execução |
| Posterior | Realizada após a execução |
| Ordinária | Programada periodicamente |
| Extraordinária | Motivada por risco ou ocorrência |
| Emergencial | Realizada diante de ameaça imediata |
| Temática | Limitada a determinado domínio |
| Integral | Abrange toda a arquitetura |
| Amostral | Examina conjunto representativo |
| Contínua | Executada por controles permanentes |

- substituição de contrato;

## 43. Proibição de destruição de evidências

Durante auditoria, será proibido:

- apagar arquivos;
- reescrever histórico;
- substituir evidências;
- modificar registros sem autorização;
- ocultar dependências;
- excluir backups;
- alterar datas;
- criar justificativa retroativa não identificada.

---

## 44. Independência

O auditor deverá possuir independência suficiente em relação ao objeto examinado.

Sempre que possível:

- o implementador não auditará sozinho sua implementação;
- o aprovador não certificará sozinho sua própria decisão;
- o responsável pelo dado não será o único validador;
- conflitos de interesse serão declarados.

---

## 45. Impedimentos

O auditor deverá declarar impedimento quando:

- possuir interesse direto;
- tiver executado integralmente o objeto;
- estiver envolvido no conflito;
- não possuir competência;
- existir relação capaz de comprometer a imparcialidade.

## 51. Verificação Git

Poderão ser utilizados:

```bash
git status --short
git branch --show-current
git rev-parse HEAD
git log --follow -- arquivo
git cat-file -e HEAD:arquivo
```

---

## 52. Verificação de arquivos certificados

Um ativo será considerado recuperável no Git quando:

```bash
git cat-file -e "HEAD:arquivo"
```

retornar sucesso.

A existência no diretório de trabalho não substitui a confirmação de recuperabilidade.

---

## 53. Validação de JSON

Arquivos JSON deverão ser validados.

Exemplo:

```bash
python -m json.tool arquivo.json >/dev/null
```

O resultado deverá ser registrado como:

```text
JSON-VÁLIDO
```

ou:

```text
JSON-INVÁLIDO
```

- backup inexistente;
- hash divergente;
- schema incompatível;
- publicação sem validação;
- correção histórica sem fonte;
- representação cultural inadequada;
- exclusão não autorizada;
- quebra de recuperação.

- decisão sem autoridade;
- competência ultrapassada;
- delegação não registrada;
- conflito de interesse omitido;
- aprovação ausente;
- desrespeito à governança.

- cronologia contraditória;
- autoria indevida;
- correção sem rastreabilidade;
- substituição silenciosa;
- apagamento da versão anterior.

- classificação inexistente;
- estado indefinido;

- incompatibilidade;
- duplicidade;
- perda de responsividade;

- restaurar arquivo;

- validar JSON;
- remover duplicidade;
- atualizar referência;
- suspender publicação;
- recuperar versão;
- corrigir permissão.

- reforço da governança.
